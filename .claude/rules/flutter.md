# Flutter (`app/`)

The replacement frontend, **not yet at parity** — `android/` and `desktop/` are
still what ships. Do not remove their code or CI lanes; the retirement trigger is
in `docs/FRONTEND_STRATEGY.md` §7 and it has not fired.

**A fresh sandbox has no `flutter` or `dart` binary**, so by default nothing
here can be analyzed, formatted or tested locally and CI is the first build. Say
so plainly rather than implying a change was verified.

**It can be installed, and for a bridge change it should be.** ~2.8 GB extracted
and about ten minutes, and the disk allowance usually needs a `cargo clean`
first — worth it whenever `MessageDto`-shaped types change, because only a real
toolchain runs the round trip that proves the codecs agree:

```bash
curl -sSL -o /tmp/f.tar.xz \
  https://storage.googleapis.com/flutter_infra_release/releases/stable/linux/flutter_linux_<FLUTTER_VERSION>-stable.tar.xz
tar xf /tmp/f.tar.xz -C /opt && git config --global --add safe.directory /opt/flutter
export PATH=/opt/flutter/bin:$PATH && (cd app && flutter pub get)
```

Take `<FLUTTER_VERSION>` from `.github/workflows/flutter.yml` — it is pinned
exactly, which is what makes a local `dart format` match CI's.

The lane, for reference:

```bash
cd app && flutter pub get
flutter analyze --fatal-infos          # infos are errors here, deliberately
flutter test
dart format --set-exit-if-changed .
```

`--fatal-infos` mirrors the repo-wide `-D warnings` posture. An unused import is
a red build.

## Bridge

Bindings are generated by flutter_rust_bridge from `crates/comrade_jni` and are
**committed**, so the Dart lane needs no Rust toolchain. Regenerate rather than
hand-editing `frb_generated*`:

```bash
cargo install flutter_rust_bridge_codegen --version <the one Cargo.toml pins>
flutter_rust_bridge_codegen generate --rust-input crate::api \
  --rust-root crates/comrade_jni --dart-output app/lib/src/rust \
  --no-add-mod-to-lib --no-web
```

**`--no-web` is not optional and leaving it off is not a silent difference.**
Without it the generator adds web codecs to `frb_generated.rs` and writes an
untracked `frb_generated.web.dart`; the `Flutter — Rust bridge round trip` job
reruns this exact command and diffs, so those extra lines fail the build with
"generated bridge code is stale" — which reads like a missing regeneration
rather than a wrong flag. Run codegen twice and check `git diff` is empty
against the committed state; that is the gate, and it is cheaper to fail here.

Rebuild `libcomrade_jni` afterwards, or the round-trip test fails on a content
hash from the previous generation.

`test/rust_bridge_roundtrip_test.dart` needs a real `libcomrade_jni`; with none
built it skips itself loudly rather than passing vacuously. Preserve that
behaviour — a silently-skipping test is worse than a failing one.

## Tests

Widget tests are per screen (`test/call_screen_test.dart`,
`test/composer_test.dart`, …) with shared setup in `test/helpers.dart`. Add to
the matching file and reuse the fakes there — widget tests run against the
in-memory fake repository, not FFI.

Existing tests assert behaviour, including some sharp invariants worth keeping
in that style: a crisis reply is never streamed, one frame complete; dark mode
is a tested property, not an eyeball check.

## Parity

When a feature exists in both `app/` and `android/`, keep the *decision* shared
and the numbers identical. Where a rule is implemented per-renderer because the
renderers differ (BoxFit vs `SCALE_ASPECT_FILL` vs CSS `object-fit`), every copy
carries the same thresholds and the same tests.
